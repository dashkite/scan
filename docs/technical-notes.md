# Technical Notes

### Parser State Management

The core of the parser operates on a state object passed continuously through transition functions. This state contains a `mode` stack array, determining the active context of the scanner. By treating modes as a stack, the parser can easily process nested constructs by pushing sub-modes and eventually popping back to the original context.

### The Parsing Loop

The `make` function iterates character-by-character over the input string. At each character, it evaluates the top mode on the stack and attempts to match the input character against the defined rules for that mode. If a specific character key is missing, it falls back to the `default` key. If no valid transition is found, it throws a detailed syntax error. When the iteration completes, the engine simulates an `"end"` character, which allows rules to perform final cleanup or validation.

### Memoization Strategy

The parser function generated by `make` is automatically wrapped in a `memoize` utility from `@dashkite/lru-cache`. This ensures that subsequent parsing requests on identical input strings resolve immediately from cache, significantly improving throughput for repeated operations.
